Just AI Images

Images compressed into words.
Any AI is the decoder.

JAI is an open image format for a world where generating pictures is cheap and local, and moving them is not. A JAI image is a few hundred bytes of description that any generative model turns back into the picture, and that a screen reader or a text-only AI agent can read as it is.

jai:A magical castle;style=anime

Those 32 bytes are a complete JAI image. The picture beside it, 189 KB as WebP, is one way to decode them.

The idea

A description is compression

JPEG throws away detail you will not miss. JAI keeps only what you would say about the picture and measures loss in meaning and appearance, not pixels. A generative model has already learned what the world looks like, so a few hundred bytes are enough for it to draw the rest.

Readable without seeing

The description is the image. A vision-impaired reader hears the author's own words through a screen reader, and a text-only AI agent reads and writes pictures with no vision model at all.

Little bandwidth

Ships, satellite links, disaster zones and text-only radio can carry a sentence where they cannot carry a photograph. A receiver with a GPU draws the picture.

Local generation

Image models are moving onto ordinary GPUs and phones, in seconds or less. Once decoding is local, the description can travel instead of the pixels.

An audience of one

Your decoder draws the pixels, so you can have them your way: adapted to your culture, softened, adjusted for your eyesight, or just in a mood you enjoy.

Today most renders still go to a hosted provider through an API key, which is fine for demos and personal renders, and the reason the reference viewer asks before every render. Read the full argument.

How it works

One document, three spellings

Text

For people

jai:A magical castle;style=anime

Description first, then ;key=value settings. Ordinary semicolons inside the description are fine.

JSON

For programs

{"jai":1,"prompt":"A magical castle","style":"anime"}

Every value is a string or a list of strings. One canonical byte sequence per document, so every image has a stable identity.

File

For files and the web

castle.jai      image/jai
gzip( JSON )

A .jai file is the JSON, gzip-compressed. It can be served, linked and embedded like any other image file.

Write one

Five rules cover almost everything

  1. Describe the picture first, as you would to someone on the phone: what is in it, where, the light, the medium.
  2. Add settings after a semicolon, each as name=value: ;style=watercolor, ;aspect=16:9, ;avoid=text.
  3. Put jai: in front when the place you write in does not already say it is JAI.
  4. Repeat a setting for several items: ;style=ink;style=loose. A model preference is only a preference.
  5. If the description starts with word=, begin with prompt= instead.
A red bicycle leaning against a whitewashed wall, afternoon sun
jai:A lighthouse on a cliff in a storm;style=watercolor;aspect=3:2
jai:A wizard in a doorway; behind him, a dragon sleeps;style=ink;avoid=text
jai:A narrow cobbled street at night, lit by neon signs, wet reflections;mode=transform;strength=0.6

The standard settings are style, avoid, aspect, model, mode, strength, seed, source, preview and animate. What each one means.

On the web

Works in every browser today

Three forms, chosen by what the page has. Browsers without JAI support keep showing the normal image, or the alt text where there is none. A JAI-aware browser or extension renders the description instead, when the reader chooses.

With an image (recommended)

<img src="castle.png"
     alt="A magical castle at dusk, mist in the valley"
     data-jai="style=anime">

The alt text is the description, for screen readers and for the model; data-jai marks the image and adds the settings.

HTML's own format negotiation

<picture>
  <source type="image/jai" srcset="castle.jai">
  <img src="castle.png" alt="A castle at dusk">
</picture>

The path a browser with built-in JAI support takes. The alt stays your page's own, shorter text.

No pixels at all: the image is JAI

<img src="castle.jai" alt="A castle at dusk"
     width="800" height="600">
![A castle at dusk](castle.jai)

A .jai file in src, in HTML or Markdown, or the same document inline as a data:image/jai,… URL. Without a viewer readers see the alt text, so it must be real prose.

The reader is always in control: nothing is rendered without their chosen provider and their consent, and the original image is always one click away. The reference browser extension shows how.

For AI agents

An installable Agent Skill

The JAI skill teaches any coding agent or assistant to write JAI from a request, describe an existing image as JAI, translate Midjourney or Stable Diffusion prompts, shorten long descriptions, embed JAI in HTML and Markdown, and validate the result.

Open SKILL.md Source on GitHub

Install

Copy the folder into your agent's skills directory, for example for Claude Code:

mkdir -p ~/.claude/skills/jai
curl -o ~/.claude/skills/jai/SKILL.md \
  https://jai.gnist.ai/SKILL.md

Or point any assistant at the URL and ask it to follow the instructions.

Build with it

An open standard, not a product

Specification

Precise enough for independent parsers and renderers: a normative parsing algorithm, canonical forms, security requirements.

Conformance tests

361 machine-readable fixtures. Two implementations that pass them agree on every input, including malformed ones.

jai.js

A dependency-free reference implementation for browsers and Node. The playground runs on it.

Everything is public domain (CC0). No account, registry or hosted service is needed, and no inference goes through anyone's servers but the reader's chosen provider.
