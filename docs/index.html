Just AI Images

Images compressed into words.
Any AI is the decoder.

JAI is an open image format for a world where generating pictures is cheap and local, and moving them is not. A JAI image is a few hundred bytes of description that any generative model turns back into the picture, and that a screen reader or an AI agent reads as it is: text all the way down.

A magical castle;style=anime

Those 28 bytes are a complete JAI image. The picture beside it, 189 KB as WebP, is one way to decode them.

The idea

A description is compression

JPEG throws away detail you will not miss. JAI keeps only what you would say about the picture and measures loss in meaning and appearance, not pixels. A generative model has already learned what the world looks like, so a few hundred bytes are enough for it to draw the rest.

Readable without seeing

The description is the image. By default it is also the alt, so a screen reader speaks the author's own words, the same words the model draws from, and an AI agent reads and writes pictures as text, with no vision model at all.

Little bandwidth

Ships, satellite links, disaster zones and packet radio can carry a few hundred bytes where they cannot carry a photograph. A receiver with a GPU draws the picture.

Local generation

Image models are moving onto ordinary GPUs and phones, in seconds or less. Once decoding is local, the description can travel instead of the pixels.

An audience of one

Your decoder draws the pixels, so you can have them your way: adapted to your culture, softened, adjusted for your eyesight, or just in a mood you enjoy.

Today most renders still go to a hosted provider through an API key, which is fine for demos and personal renders, and the reason the reference viewer renders only when you ask, unless you allow a site to render automatically. Read the full argument.

How it works

One document, three places

A JAI document is a description plus optional settings. HTML and files carry it, and each place says by itself that it holds JAI, in exactly one form.

Attribute

On an image you already have

data-jai="style=anime"

The text form: description first, then ;key=value settings. The image's alt is the description unless data-jai gives one.

data: URL

An image with no pixels, inline

data:image/jai,A%20magical%20castle;style=anime

The same text form, percent-encoded, in src or a <source> srcset. The media type marks it.

File

For files and the web

castle.jai      image/jai
gzip( {"jai":1,"prompt":"A magical castle","style":"anime"} )

A .jai file is gzip-compressed canonical JSON: one byte sequence per document, so every image has a stable identity. It is served, linked and embedded like any other image file.

Write one

Four rules cover almost everything

  1. Describe the picture first, as you would to someone on the phone: what is in it, where, the light, the medium.
  2. Add settings after a semicolon, each as name=value: ;style=watercolor, ;aspect=16:9, ;avoid=text.
  3. Repeat a setting for several items: ;style=ink;style=loose. A model preference is only a preference.
  4. If the description starts with word=, begin with prompt= instead.
A red bicycle leaning against a whitewashed wall, afternoon sun
A lighthouse on a cliff in a storm;style=watercolor;aspect=3:2
A wizard in a doorway; behind him, a dragon sleeps;style=ink;avoid=text
A narrow cobbled street at night, lit by neon signs, wet reflections;mode=transform;strength=0.6

The standard settings are style, avoid, aspect, model, mode, strength, seed, source and preview. What each one means.

On the web

Works in every browser today

Three carriers, chosen by what the page has. Browsers without JAI support keep showing the normal image, or the alt text where there is none. A JAI-aware browser or extension renders the description instead, when the reader chooses.

With an image (recommended)

<img src="castle.png"
     alt="A magical castle at dusk, seen from below"
     data-jai="style=anime;prompt/flux=Lit windows glow warm">

data-jai marks the image and holds the settings. The alt is the description: written once, spoken by screen readers exactly as written, and drawn by the model. Start data-jai with the description instead, and the alt stays your page's own, shorter text.

HTML's own format negotiation

<picture>
  <source type="image/jai" srcset="castle.jai">
  <img src="castle.png" alt="A castle at dusk">
</picture>

The path a browser with built-in JAI support takes. The alt stays your page's own text.

No pixels at all: the image is JAI

<img src="castle.jai" alt="A castle at dusk"
     width="800" height="600">
![A castle at dusk](castle.jai)

A .jai file in src, or the same document inline as a data:image/jai,… URL. Markdown's image syntax renders to the same <img> without a size, so the document's aspect sets the shape. Without a viewer readers see the alt text, so it must be real prose.

The reader is always in control: nothing is rendered without their chosen provider and their consent, and the original image is always one click away. The reference browser extension shows how.

For AI agents

An installable Agent Skill

An agent reads and writes JAI images as text. The JAI skill teaches any coding agent or assistant to write JAI from a request, describe an existing image as JAI, shorten long descriptions, put JAI on pages and in .jai files, and validate the result.

Open SKILL.md Source on GitHub

Install

Copy the folder into your agent's skills directory, for example for Claude Code:

mkdir -p ~/.claude/skills/jai
curl -o ~/.claude/skills/jai/SKILL.md \
  https://jai.gnist.ai/SKILL.md

Or point any assistant at the URL and ask it to follow the instructions.

Build with it

An open standard, not a product

Specification

Precise enough for independent parsers and renderers: a normative parsing algorithm, canonical forms, security requirements.

Conformance tests

Machine-readable fixtures for every rule. Two implementations that pass them agree on every input, including malformed ones.

jai.js

A dependency-free reference implementation for browsers and Node. The playground runs on it.

Everything is public domain (CC0). No account, registry or hosted service is needed, and no inference goes through anyone's servers but the reader's chosen provider.
