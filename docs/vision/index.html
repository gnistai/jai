Vision

Moving pixels is expensive.
Making them is getting cheap.

JAI is an image format for the world that follows: send the few hundred bytes that say what a picture shows, and let a generative model on the other end draw it.

The idea

A description is compression

Every image format trades bytes for distortion. PNG keeps every pixel. JPEG discards detail your eye will not miss. JAI takes the same trade much further: it keeps only what a person would say about the picture, and discards the rest.

That is not a different kind of thing from image compression; it is the same trade taken much further. The difference is in how distortion is measured: in meaning and appearance, not pixels. A JAI decoding will not match the original pixel for pixel, and two models can draw visibly different pictures, but a good description makes them show the same things, arranged and lit the same way, from a thousand times fewer bytes.

It works because the decoder brings a prior. A generative model has already learned what harbours, castles and dusk light look like, so the code only has to say which ones, where and how. Speech coding has relied on this for decades: a vocoder sends the parameters of a model of the voice instead of the waveform, and a CELP encoder chooses its excitation by running the decoder inside the encoder and keeping what sounds closest. A JAI encoder does the same, except that it does not know which model the reader will use, so it tunes for a set of likely ones.

Where it matters

The use cases

01 Readable without seeing

A JAI image is text first. A vision-impaired reader's screen reader speaks the author's own description, the same words the model draws from, so the text alternative is always there and always matches the picture. A text-only AI agent reads and writes images directly, with no vision model: it can understand, search, translate, compare and edit a picture in the medium it already uses.

02 Little bandwidth, enough compute

Ships and aircraft, satellite plans with data caps, rural and disaster-zone networks, and text-only channels such as SMS, packet radio and mesh networks can carry a sentence where they cannot carry a photograph. A receiver with a GPU draws the picture. This suits illustrative and situational images, not measurements: where the pixels are the data, send the pixels.

03 Local generation

Generating an image is moving onto ordinary GPUs and recent phones, in seconds or less with distilled models. If browsers come to decode JAI natively, a page could offer the JAI source in a <picture> element and the browser would fetch the raster only when rendering fails. Today's viewers still download the raster.

04 An audience of one

Your decoder draws the pixels, so you can ask for them your way: adapted to your culture, softened for content you would rather not see, adjusted for your eyesight, with the text in the picture in your language, or just in a mood you enjoy. The author's description stays the same, and the personalised render is always labelled as such.

05 Longevity and any resolution

A description does not age with its codec and has no fixed resolution. Rendered next year by a better model, or for a larger screen, the same few hundred bytes give a better picture, the way vector graphics outlive the screens they were drawn for.

06 Declared provenance

A JAI document says it is a description, and renderers label what they draw as generated. The format never claims that a render records an event, even when the description was encoded from a photograph.

How it works

Encoding and decoding

Decoding is the generative model turning the description back into pixels. Encoding is the harder half, and it works by analysis by synthesis: describe the image, render the description with the models you want to support, compare each render with the original, revise the words, repeat. The loop stops when the renders match as well as they are going to, or when the time or money set aside runs out. The Earthrise example shows one run of the reference encoder: a 64 KB photograph became a 465-byte document.

Like a font stack in CSS, a document can name the models it was tuned for, in order of preference. It carries a core description that every model understands, plus small refinements for particular models, so each one reconstructs the image as well as it can and any other model still gets the core.

jai:A girl holding a red balloon in a park at dusk;prompt/flux=The balloon floats high above her;prompt/imagen=The balloon is glossy;model=flux;model=imagen

One core description, with refinements for two models in the order of preference. Any other model renders the core alone.

Today

The stage we are at

Most people do not have a fast image model on their machine yet, so today's renders usually go to a hosted provider, paid for with an API key. That is good for demonstrations and for personal, audience-of-one renders, and it is why the specification is careful about consent, budgets and what leaves the browser. The format does not depend on it: the same documents decode on a local GPU, and get better as models do.

Where exact pixels matter more than size, such as evidence, medical images, diagrams and screenshots of text, keep the raster. JAI can still travel alongside it as the searchable, editable source.
